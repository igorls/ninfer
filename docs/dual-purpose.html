Closed-set readout, leftover mass

The same Qwen weights that write chat also answer a closed list of option tokens. logprob is that list, renormalised. outside_mass is everything they put elsewhere. If the remainder is high, those weights can still think — they are not a second model.

On the engine today

This is a readout of the model you already serve for chat and chain-of-thought.

candidate_logprobs
Up to 1024 closed-set options, each exactly one token. The reported logprob is the softmax over that list only.
raw_logprob
Log softmax over the whole vocabulary, before temperature, penalties, or truncation. A client can fit its own calibration map.
outside_mass
Vocabulary-wide probability the model put outside the candidate list. Jev cannot emit this; a dual-purpose model can.
POST /v1/score
One shared prefix, 1–256 isolated questions. Questions never see each other’s answers. The first question publishes the prefix; the rest read it.
enable_thinking
A per-request template flag. Turn it on from the reject slice. Do not train the model to skip thinking.

The gate

Pass 1 is always a typed read at T=1. If outside_mass is high, or the candidate distribution is flat, pass 2 uses the same weights with thinking on — then either re-reads the candidates or generates.

High remainder means the model wanted to write something you did not list. A dedicated decision model has no such leftover; it can only be wrong inside the schema.

Isolation

Each question is its own one-token request against the published prefix. Later questions do not attend to earlier answers. Packing many questions into one generated prompt is a different product: quality drops, and later generation on that prefix picks up exam-mode contamination.

Fusing the forward — one prefill, N decode branches sharing KV — is engine work. Concatenating questions is not.

We will not RLCD the served weights, distill Jev’s probabilities into Qwen, or merge a decision LoRA into the chat path. Those are how you get a model that cannot write.

Letter bias before any fine-tune

A dual-purpose Qwen has exam priors on A/B/C. The score API already accepts integer token ids and arbitrary one-token strings. Shuffle option order. Prefer scoring the criterion string over the letter. Hierarchical choice when the set is large — seventy-seven intents is where a letter readout fails and option text might not.

Order of work

  1. Measure the gate on our own labels: outside_mass × candidate entropy × optional thinking pass. Coverage versus error, not a vendor multiplier.
  2. Letter-shuffle and criterion-string readout on the same set. Prompt convention, not a new head.
  3. Per-domain temperature or isotonic maps on the pre-sampling logits we already return. Off the generation path.
  4. Candidate-only logit gather, and a fused shared-prefix /v1/score. MTP stays off on the scored token; chat graphs stay untouched.
  5. Request-scoped answer-token LoRA only if that ceiling is still short of the slice we care about. LoRA off must remain bit-identical to today’s checkpoint on generation and thinking evals.

Jev’s remaining moat is calibrated isolation in one forward, not intelligence. NInfer already has isolation and the logits. The dual-purpose product is the reject-into-CoT seam. Calibration is a map we fit. Generation stays the default path.
